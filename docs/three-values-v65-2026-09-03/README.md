# 三项数值版本：实现与平衡审计

日期：2026-09-03。实际界面版本：v6.5。

## 采用规则

- 保留人物的金钱、额外耗电、躁动；保留剩余站数、六个站位、人物关系和请离。
- 初始电量 20，上限 24。每站基础耗电从 2 降为 1，加上人物明确标注的额外耗电。节能不能让一站耗电低于 1。
- 游客额外耗电 1/站、车费 22；教练额外耗电 1/站、车费 20。神秘人、百变人可有 0–1 额外耗电；复制人可以复制它。
- 移除载重上限、超载惩罚、耐心递减和因耐心耗尽而离开。旧字段仅为历史报告/实验的类型兼容保留，不参与实际决策；生成的 patience 为 0，兼容 totalWeight 返回 0。
- 儿童缺少恋人、护士或音乐家邻座时，每逢偶数层躁动 +1。有照护邻座则免除。
- 躁动达到上限的三分之二（向上取整）时，人物技能和邻座冲突的正向躁动 ×2；舒缓不变，楼层波次和拥挤不翻倍。使用出发时状态，不在同层连锁翻倍。
- 检查员偶数层检查：人物额外耗电合计为 0 时节能 1，否则躁动 +1（高躁动时 +2）。
- 稳压模块替代承重升级：抵消最多 1 点人物额外耗电，每局只能安装一次。礼宾服务改为新乘客到站小费 +3/级。
- 充电仍为 3 金币/电。十层路段基础耗电 10；建议充到 22 为后续上客留余量，不承诺必定够用。
- 神秘人隐藏车费；百变人每层更新三值和偏好；复制人按邻座分别复制耗电、金钱或躁动（含关系），不重复、不递归、不泄露隐藏车费。

## 模拟设计和结果

共 19,680 局从正常开局开始的完整模拟，另有 360 次从 41 层、高躁动局面开始的条件测试。共 970,787 次楼层结算，预报核对错误为 0。600 层只是模拟保护上限，不是游戏终点；本轮没有任何样本被这个上限截断。

| 阶段 | 局数 | 用途 |
| --- | ---: | --- |
| screen | 5,760 | 6 个参数候选、12 种策略、每项 80 局 |
| holdout | 8,000 | 旧模型与选中模型、20 种策略、每项 200 局，新种子 |
| countercheck | 1,920 | 选中模型与提高重耗电人物车费、8 种策略、每项 120 局 |
| final | 4,000 | 最终实际规则、20 种策略、每项 200 局，再换新种子 |
| crises | 360 | 6 种策略各 60 次高躁动恢复局面，不能混作完整开局样本 |

种子：screen/countercheck/crises 为 984681317；holdout 为 985327199；final 为 986564729。相同种子不保证不同规则下发牌完全一致，因为随机数调用路径可能分岔。策略不读取未来候客，规划使用独立随机流，神秘人车费对策略隐藏。

最终独立样本，每种策略 200 局：

| 策略 | 平均结束层 | 断电失败 | 躁动失败 | 通过首商店 |
| --- | ---: | ---: | ---: | ---: |
| 均衡三人 | 36.39 | 53 | 147 | 192 |
| 贪心六人 | 18.62 | 48 | 152 | 177 |
| 谨慎六人 | 54.14 | 61 | 139 | 185 |
| 契约前瞻四人 | 103.12 | 4 | 196 | 200 |
| 配对前瞻六人 | 110.93 | 3 | 197 | 200 |
| 避免额外耗电四人 | 100.79 | 0 | 200 | 200 |
| 避免额外耗电六人 | 113.32 | 0 | 199 | 200 |
| 不买升级 | 31.46 | 112 | 88 | 185 |
| 不买稳压模块 | 40.58 | 127 | 73 | 185 |

避免额外耗电六人另有 1 次引信失败。该策略在做决定时惩罚可见的额外耗电，不保证动态人物后续永不变耗电。

选择基础耗电 1 的原因：基础 2 再叠加人物消耗时，早期过多局面被断电截断。仅按当前乘客计算充电需求的候选表现更差，保留充电余量。单纯把游客/教练车费再提高到 28/26 没有改善整体策略，并增加部分早期断电，未采用；廉价充电候选也未采用。

重要限制：低耗电策略仍偏强（上一组独立样本均值 117.08，配对前瞻 112.52；最终 113.32 对 110.93）。不能宣称已经不存在优势打法，也不能将模拟结果当成人类胜率或趣味性证明。当前修改解决的是规则可读性和基础资源张力，后续应观察低耗电/稳压模块的选择率及高耗电角色的真实接受率。

## 确定性回归

`npm run verify` 使用当前正式模型：

- 52,920 个定向人物对、站位、楼层奇偶、高躁动组合；独立计算关系效果核对。
- 48,000 次随机状态结算，包含神秘人、百变人、复制人，核对预报范围、结算、输入不被修改。
- 取消载重/耐心惩罚、基础耗电下限、稳压模块、请离、隐秘车费、升级、儿童照护、失败原因和三项反馈覆盖。
- 音效静音、队列、取消和兼容回退测试。

`npm run verify:legacy` 另外在基线提交中运行历史回归；只证明保存的旧模型可复核，不冒充当前规则测试。类型检查、改动文件检查和生产构建通过。浏览器检查另见 `browser-verification.md`。

## 证据与复核

每份 JSON 保存模型各模块 SHA-256、随机种子及执行器 SHA-256。`sources/<sha256>.txt` 保存实际运行过的模块和执行器，包含已被否决的早期参数候选。`summary.json` 汇总全部报告；`scripts/summarize-three-values.ts` 校验局数、零预报错误和最终正式模型五个核心模块的哈希一致性。

审计脚本从当前模型复制出独立临时目录。早期 `base1` 候选基于当时的基础耗电 2，不能在已改为 1 的当前模型上直接重复参数替换；重放历史候选应按 JSON 中的哈希恢复对应源文件和执行器，再使用记录的种子、策略和局数。当前实际规则可使用 release 变体和新的输出阶段目录继续测试，脚本拒绝覆盖已有结果。
